# Приложение: формат киберграфа

CID — всегда CID v0:
содержимое оборачивается в стандартный IPFS-блок (UnixFS dag-pb), хешируется sha2-256,
и хеш кодируется в base58
— получается строка вида Qm….
Тот же результат даёт `ipfs add --cid-version=0`.

Подписант (поле `signer` в записи) — это CID его публичного ключа.
В этом формат сознательно расходится с Bostrom,
где подписант записывается адресом `bostrom1…` (см. «Основы»):
формат берёт CID ключа,
чтобы подписант был адресуем, как любой другой CID.
Кодирование подписанта должно быть одно:
если одного подписанта можно записать по-разному (адресом, голым ключом),
один и тот же акт получит разные производные CID киберлинка.
Ломается адресация акта:
`deny_link`, отзыв собственного киберлинка, оспаривание согласия конкретного подписанта
— рёбра, посчитанные от разных кодировок подписанта, целят в разные CID,
и их повторы не совпадают при агрегации.
Страдает и взвешивание:
один подписант под двумя кодировками читается как два.
Адрес — хеш ключа, обратно ключ не вычисляется;
для конверсии ключ достают из транзакции, несущей киберлинк,
— транзакция публикует ключ подписанта рядом с подписью —
и считают его CID
— без этого шага производный CID киберлинка Bostrom не посчитать.

Производный CID — всегда CID v0 канонических байтов записи.
Запись плоская, все значения — строки:
вложенная запись сначала заменяется своим CID.
Ключи отсортированы по порядку их UTF-8-байтов
— для ключей выпуска это `about`, `cid_from`, `cid_to`, `op`, `signer`.
JSON компактный, без пробелов вне строк,
и заканчивается ровно одним `\n`.
Любой производный CID воспроизводится командой `printf '<запись>\n' | ipfs add --only-hash --cid-version=0`.
В записях выпуска заглавные буквы (A, B, X, Qm1…), `signer` и `hash("…")` обозначают CID
— в байтах это строки в кавычках.
Два частных случая:
адрес ребра — `{"cid_from":A,"cid_to":B}`,
производный CID киберлинка — `{"cid_from":A,"cid_to":B,"signer":signer}`.
Кодирование должно быть одно для всех
— иначе, как и с двумя кодировками подписанта выше, один и тот же акт получит разные производные CID.
