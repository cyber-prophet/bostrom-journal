# Киберграф

Киберграф — это общее информационное пространство. Его элементы — *киберчастицы* (cyberparticle), далее по тексту просто *частицы*: единицы данных, и у каждой есть свой адрес — CID. Частицы связаны киберлинками. Технически киберграф — это структура данных из таких киберлинков, и каждый киберлинк — это подписанная нейроном запись (record) вида:

```
{
    cid_from: Qm1
    cid_to: Qm2
    neuron: Qm3
}
```

cid_from и cid_to — это CID (content identifier) двух связываемых частиц: IPFS-хеши, уникально идентифицирующие содержимое файлов (безотносительно их имени). Пара cid_from → cid_to — это *ребро* киберграфа, направленное из cid_from в cid_to; частицы — его вершины. *Кибернейрон* (cyberneuron), далее по тексту просто *нейрон*, — это агент (например, человек, ai, контракт или сенсор), который создал и подписал киберлинк; он адресуется своим CID (Qm3), поэтому на нейрона можно сослаться, как на любое содержимое. Частицей нейрон становится, когда его CID стоит в ребре. Точное кодирование зафиксировано в приложении «формат киберграфа».

Благодаря тому, что все три поля — cid_from, cid_to и нейрон — простые текстовые строки, мы можем объединять их в одну строку через запятую и от полученной строки считать IPFS-хеш — производный CID. Хеш двойки "Qm1,Qm2" — *адрес ребра*: он не содержит нейрона и потому один для всех, кто связал те же частицы, — он адресует то, *что* утверждается. Хеш тройки "Qm1,Qm2,Qm3" — производный CID киберлинка: он адресует акт конкретного нейрона — *кто* утверждает. Оба адреса можно использовать для формирования других киберлинков — это позволяет выпускать инструкции по интерпретации рёбер и конкретных киберлинков при помощи других киберлинков. До такого использования производный CID — только адрес: частицей он, как любой CID, становится, когда стоит в ребре.

В этом выпуске журнала мы придумываем и осмысляем возможные подходы — открытые соглашения для кодирования и интерпретации инструкций по обработке киберграфа.
