# Киберлинк и киберграф

Файл в наиболее частом понимании — это поименованная совокупность данных: текстовый документ, картинка, видео, архив и т.д. Для целей этого выпуска журнала мы:

1. под файлом будем понимать только его содержимое — имя не участвует.
2. из всех типов файлов оставим только текстовые (человекочитаемый текст или машиночитаемые структуры данных, сериализованные в JSON).

Файл — носитель смысла: смысл возникает у читателя при чтении его содержимого.

Киберлинк — это утверждение подписанта: «эти два файла связаны». Подписант — агент (например, человек, AI), который создал и подписал киберлинк. Киберграф хранит и связь, и того, кто её утверждает, — но не смысл: как книга хранит только текст, напечатанный на бумаге, а смысл возникает у читателя, так и здесь смысл утверждения порождается при чтении, интерпретацией (см. «Соглашения»).

Киберграф — это структура данных, состоящая из киберлинков. Каждый киберлинк — это подписанная запись (record) вида:

```
{
    cid_from: Qm1
    cid_to: Qm2
    signer: Qm3
}
```

`cid_from` и `cid_to` — это CID двух связываемых файлов. CID (content identifier) — адрес файла: IPFS-хеш, уникально идентифицирующий содержимое. Пара `cid_from → cid_to` — это *ребро* киберграфа, направленное из `cid_from` в `cid_to`; файл становится вершиной, когда его CID стоит в ребре. Поле `signer` — это CID подписанта (Qm3), поэтому сослаться на него можно, как на любой файл, и вершиной подписант становится по тому же правилу — когда его CID стоит в ребре. Точное кодирование зафиксировано в приложении «формат киберграфа».

Благодаря тому, что все три поля — `cid_from`, `cid_to` и `signer` — простые текстовые строки, мы можем, например, объединять их в одну строку через запятую и от полученной строки считать IPFS-хеш — производный CID. Хеш двойки `"Qm1,Qm2"` — *адрес ребра*: он не содержит подписанта и потому один для всех, кто связал те же файлы, — он адресует то, *что* утверждается. Хеш тройки `"Qm1,Qm2,Qm3"` — производный CID киберлинка: он адресует акт конкретного подписанта — *кто* утверждает. Оба адреса можно использовать для формирования других киберлинков — это позволяет выпускать инструкции по интерпретации рёбер и конкретных киберлинков при помощи других киберлинков. До такого использования производный CID — только адрес: вершиной он, как любой CID, становится, когда стоит в ребре.

В этом выпуске журнала мы придумываем и осмысляем возможные подходы — открытые соглашения для кодирования и интерпретации инструкций по обработке киберграфа. Придуманное — лишь плод мысленных упражнений, ещё не проверенный практикой. Реализация покажет, что в соглашениях менять. Однако это задача будущего.
